# REVIEW.md

## Defects found in the starter code

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | The calculation does not correctly handle the required IST time zone, overnight shifts, and the rule that late minutes are floored from the shift start after the strict 10-minute grace period. | Test punches at 09:40:00 and 09:40:01 for a 09:30 shift, and test an overnight shift. | Added IST-aware time handling, overnight shift-start resolution, whole-second truncation, and the required grace-period calculation. |
| 2 | `compute_work_hours` | Python's built-in `round()` does not guarantee the required decimal half-up rounding. | Test durations whose calculated hours are exactly halfway between two hundredths. | Used `Decimal` and `ROUND_HALF_UP` to round work hours to two decimal places. |
| 3 | `compute_overtime` | The calculation does not handle overnight shifts correctly and does not enforce the minimum of 30 whole overtime minutes. | Test punch-outs before shift end, 29 minutes after shift end, and 30 minutes after shift end; also test an overnight shift. | Added overnight shift-end handling and return overtime only when the floored elapsed minutes are at least 30. |
| 4 | `EmployeeIn` and `PunchInIn` models | The starter models do not validate required field formats, timestamp bounds and types, or the allowed punch-in status values. | Submit malformed employee codes, invalid dates or shift times, seconds instead of epoch milliseconds, and an unsupported status. | Added Pydantic field validation and model-level checks for the required formats and business constraints. |
| 5 | `health` | The endpoint returns success without checking whether MongoDB is reachable. | Stop or disconnect MongoDB and call `GET /health`. | Added a MongoDB ping and return HTTP 503 when the database is unavailable. |
| 6 | `create_employee` | Duplicate checking before insertion is vulnerable to concurrent requests, and the creation timestamp is not consistently handled as UTC epoch milliseconds in the response. | Send concurrent requests with the same employee code and check the `created_at` response format. | Added a unique employee-code index, duplicate-key handling, and UTC epoch-millisecond response formatting. |
| 7 | `list_employees` | Pagination uses `page * page_size` as the skip value, so page 1 skips the first page. The total count also ignores the department filter, and results are not explicitly sorted. | Request page 1 with a known number of employees; then filter by department and compare `total` with the filtered count. | Corrected the skip calculation, counted matching documents, and added deterministic sorting and pagination validation. |
| 8 | `punch_in` | The starter does not safely handle an unknown employee, uses local-time-dependent timestamps, calculates the attendance date without the required IST and overnight-shift rules, and can create duplicate records under concurrent requests. | Punch in for an unknown employee; test a UTC timestamp near the IST date boundary, an overnight shift, and simultaneous duplicate requests. | Added employee-not-found handling, UTC/IST conversion, attendance-day resolution, timestamp normalization, and a unique attendance key with duplicate-key handling. |
| 9 | `list_attendance` | It loads all matching records into application memory and sorts and paginates in Python. It also does not validate date ranges or pagination parameters as required. | Test with a large attendance collection, invalid date ranges, and invalid page values. | Moved filtering, sorting, and pagination into MongoDB, added input validation, and used appropriate indexes. |
| 10 | Missing punch-out endpoint | The starter does not implement `POST /attendance/punch-out`. | Call the endpoint described in `openapi.yaml`; it is absent from the starter. | Implemented punch-out validation and computation of work hours, overtime and half-day status. |
| 11 | Missing regularization endpoint | The starter does not implement `PATCH /attendance/{emp_code}/{date}` or the required correction audit trail. | Attempt a correction and check that the corrected fields and history entry are returned. | Implemented correction validation, recalculation of derived fields, and append-only audit history. |
| 12 | Missing analytics endpoints | The starter does not implement the required monthly employee summary, department summary, late leaderboard, or department trend. | Compare the registered routes with the required paths in `openapi.yaml`. | Implemented the required analytics endpoints using MongoDB aggregation and the specified business rules. |
| 13 | Missing explain endpoint and indexes | The starter does not provide `/admin/explain/{endpoint}` or create the required indexes at startup. | Call the explain endpoint and inspect the database indexes. | Added startup index creation and explain-plan handling for the supported endpoints. |

## Reviewed but not considered defects

- The default MongoDB URI is useful for local development; deployment-specific connection settings are supplied through environment variables.
- The `history` field starts as an empty list because the contract requires history to record manual corrections, not ordinary punch-in or punch-out events.
- Employee codes are business identifiers supplied by the client; they should not be replaced by MongoDB's internal `_id`.
